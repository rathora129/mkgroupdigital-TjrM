# MK Group Digital

Production website for MK Group Digital — a full-service digital agency working with clients in India and worldwide.

Live domain: `https://mkgroupdigital.com`

## Stack

- Next.js 16 (App Router, JavaScript/JSX) with Turbopack
- React 19
- styled-components 6 with an SSR registry and a shared design-token theme
- framer-motion for page transitions, scroll reveals, hover states and the mobile menu
- Formik + Yup for the contact form (one schema shared by the browser and the API route)
- lucide-react for icons
- next/font (Space Grotesk + Inter) and next/image

## Commands

```bash
npm install
npm run dev     # development server on http://localhost:3000
npm run lint    # ESLint
npm run build   # production build
npm start       # serve the production build
```

Copy `.env.example` to `.env.local` before wiring contact delivery. The site runs without any environment variables; the contact form will then explain that online delivery is unavailable and offer email and WhatsApp instead.

## Project structure

```
src/
  app/                 routes, metadata, sitemap, robots, API route
  components/
    layout/            Header (sticky, mega menu, mobile overlay), Footer, announcement bar
    sections/          Homepage and shared page sections
    pages/             Route-level views
    ui/                Buttons, cards, accordion, reveal, logo, icons, layout primitives
  data/                Site config, services, projects, industries, FAQs, legal copy
  lib/                 SEO metadata helper, JSON-LD, contact schema, styled-components registry
```

Editable content lives in `src/data/`. Business details, navigation, contact links and the WhatsApp message are in `src/data/site.js`.

## Contact form delivery

A floating WhatsApp button (`src/components/layout/WhatsAppFloat.jsx`) renders on every page, bottom-right, linking to the prefilled `wa.me` chat. The contact page additionally shows an Instagram QR card (supplied artwork at `public/contact/mkgroupdigital-qr.png`, served unmodified) and a "Not sure what you need?" panel for early-stage enquiries.

`POST /api/contact` accepts JSON:

```json
{
  "fullName": "…",
  "email": "…",
  "phone": "…",
  "company": "…",
  "service": "…",
  "budget": "…",
  "contactMethod": "WhatsApp | Email | Phone",
  "details": "…",
  "website": ""
}
```

Only `fullName`, `email`, `service`, `budget` and `contactMethod` are required; phone, company and details are optional. The service dropdown includes two guidance options for visitors who do not know what they need yet, and the budget dropdown always offers "Not sure yet".

The route re-validates every field with the same Yup schema as the form, rejects the hidden `website` honeypot, caps bodies at 50 KB and never exposes credentials to the browser. Delivery priority:

1. **Resend** — used when `RESEND_API_KEY` and `CONTACT_FROM_EMAIL` are both set. `CONTACT_FROM_EMAIL` must be a verified sender in the Resend account. Replies go to the enquirer's email; `CONTACT_TO_EMAIL` defaults to `query@mkgroupdigital.com`.
2. **Webhook** — used when `CONTACT_WEBHOOK_URL` is set and Resend is not. The route posts `{ type: 'contact-enquiry', submittedAt, data }` to that URL.
3. **Not configured** — if neither is set, the route returns `503` with `code: "NOT_CONFIGURED"`. The form shows an honest fallback with `mailto:query@mkgroupdigital.com` and the prefilled WhatsApp link. Nothing is silently discarded, and no success message is shown.

Provider failures and timeouts (10s) return `502` with `code: "DELIVERY_FAILED"` and the same fallback. A success response is only returned after the provider accepts the message.

Environment variables (see `.env.example`):

| Variable | Required | Purpose |
| --- | --- | --- |
| `RESEND_API_KEY` | For Resend delivery | Resend API key |
| `CONTACT_FROM_EMAIL` | For Resend delivery | Verified sender address |
| `CONTACT_TO_EMAIL` | No | Lead recipient, defaults to `query@mkgroupdigital.com` |
| `CONTACT_WEBHOOK_URL` | For webhook delivery | Automation endpoint for validated leads |

Set these in the hosting provider's environment settings, not in the repository. `.env`, `.env*.local` and `.next` are ignored by git.

## Known placeholders

- **Instagram** — `siteConfig.social.instagram` points at `https://www.instagram.com/` with `instagramPending: true` because the real handle was not supplied. Replace the URL in `src/data/site.js` and clear the flag once the account is confirmed. The QR artwork on the contact page is used exactly as supplied.
- **Testimonials** — the homepage section uses clearly labelled sample copy, as specified. No client names, ratings, review schema or performance metrics are claimed anywhere on the site. Replace the samples in `src/components/sections/TestimonialsSection.jsx` only with approved real quotes.
- **Pricing** — every price on `/pricing` is an indicative starting figure; the page states that final cost is confirmed in a written quote, that hosting/domain/third-party/ad spend are separate unless included, and that no leads, sales or advertising results are guaranteed.

## SEO and accessibility

- Unique title/description and canonical URL per route via `src/lib/seo.js`, plus Open Graph and Twitter cards.
- Organization schema in the root layout, Service and Breadcrumb schema on service pages, Article and Breadcrumb schema on project pages, ContactPage schema on `/contact`.
- Generated sitemap (20 URLs) and robots file.
- Semantic landmarks, a skip link, labelled navigation and forms, `aria-expanded`/`aria-controls` on menus, visible focus states, Escape-to-close and a focus trap in the mobile menu.
- Motion respects `prefers-reduced-motion`; animations are limited to transform and opacity.
